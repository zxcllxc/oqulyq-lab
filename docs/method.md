# Методика Oqulyq Lab

Код: `src/lib/analytics.ts` (темы, честное сравнение, часы), `src/lib/diagnostics.ts` (задания, динамика, раннее предупреждение), `src/lib/importer.ts` (проверка импорта). Тесты: `tests/*.test.ts`, запуск `npm test`.

## 1. Трудные темы
- Средний балл темы = среднее по всем результатам учеников; усвоение = доля учеников с баллом ≥ 60 (`PASS`).
- Цель `TARGET` = 70. «Трудная» (метка в интерфейсе) — средний балл < 65. Пустая тема трудной не считается.

## 2. Честное сравнение учебников
- Единица анализа — класс (средний балл класса по теме): большая школа не перевешивает маленькую.
- Ожидаемый балл: `a(тема) + b · baseline`, baseline — итог класса за прошлый год.
  - `b` — наклон МНК, объединённый **внутри групп «тема × учебник»** (ANCOVA). Так эффект учебника, который чаще берут сильные классы, не утекает в наклон (иначе разница учебников занижается).
  - `a(тема)` = среднее (балл − b·baseline) по всем классам темы.
- Остаток = факт − ожидание. Эффект учебника = средний остаток его классов (общий эффект — среднее по классам их средних остатков). Это отклонение **от среднего по всем учебникам**, а не разница между двумя учебниками: при двух учебниках с разницей 6 п.п. каждый получит ±3, и порог 3 п.п. относится именно к этому отклонению.
- 95% ДИ = эффект ± t(k−1) · σ / √k, t — квантиль Стьюдента (при k = 3 это 4,30, а не 1,96).
- Вердикт: k < 3 → «мало данных»; baseline не меняется (например, импорт без колонки baseline) → «нет уровня на входе», выводов «выше/ниже» нет; ДИ целиком выше 0 и эффект ≥ 3 п.п. (`MIN_EFFECT`) → «выше ожидаемого»; ниже 0 и ≤ −3 → «ниже ожидаемого»; иначе «разница < 3 п.п. или не доказана».
- Ограничения: один фактор (уровень на входе); нет поправки на множественные сравнения по темам.

## 3. Причина просадки темы
- Тема ниже цели больше чем на 2 п.п. (`DEAD_ZONE`), и у какого-то учебника вердикт «ниже ожидаемого» с эффектом ≤ −(разрыв/2) → проблема главы, часы не добавляем.
- Иначе → дефицит часов. Если у всех учебников по теме «мало данных» или «нет уровня на входе», объяснение говорит «влияние учебника не проверено». Если тем-доноров нет вовсе, объяснение говорит, что нужен пересмотр годового объёма.

## 4. Перераспределение часов
- Годовой объём фиксирован. План темы по умолчанию — 6 ч, если в данных нет часов. Часы принимаются только целыми.
- Получатели: темы с дефицитом часов; потребность 1 ч за каждые 7 п.п. разрыва, от 1 до 3 ч.
- Доноры: темы выше цели на 2+ п.п.; каждая отдаёт целые часы, оставаясь ≥ 75% плана (округление вверх).
- В зоне ±2 п.п. вокруг цели часы не трогаем (шум не двигает план).
- Раздача по кругу: сначала по 1 ч каждой теме по убыванию разрыва, затем вторые часы и т. д., пока есть резерв.
- «Что если»: прогноз +2,5 п.п. за час — демо-допущение (подписано в интерфейсе).

## 5. Анализ заданий
- p — доля верных ответов; r — точечно-бисериальная корреляция вопроса с суммой остальных вопросов (rest-score, без самого вопроса).
- Флаги только при n ≥ 30: «плохой вопрос» r < 0,15 (кроме случая, когда все ответили одинаково); «слишком сложный» p < 0,2; «слишком лёгкий» p > 0,95; «ловушка» — неверный вариант, который выбирают ≥ 25% верхних 27% учеников.

## 6. Динамика и раннее предупреждение
- Остатки класса берутся за вычетом эффекта главы учебника — среднего остатка **других** классов той же группы «тема × учебник» (leave-one-out), чтобы слабая глава III–IV четверти не выдавалась за «сползание» классов. Если других классов меньше 3, эффект главы не вычитается.
- Падение = средний остаток III–IV четв. − I–II четв.; 95% ДИ по Уэлчу с t-квантилем (консервативно df = min(n₁, n₂) − 1). Флаг: падение ≥ 4 п.п. и ДИ целиком ниже 0.

## 7. Импорт
- Обязательные колонки: school, class, textbook, topic, score. Строки отклоняются по причинам: нет поля, балл не число, балл вне 0–100, дубликат (при колонке student).
- baseline пустой/некорректный → подставляется 60 и считается в отчёте («подставлено в N строках»); 0 — допустимое значение. Нет колонки baseline или подставлено больше 20% строк → честное сравнение отключается.
- quarter — целое 1–4, иначе берётся из программы. Колонки ФИО не читаются. Лимит файла 10 МБ и 500 000 строк. Файл разбирается в браузере и на сервер не отправляется.
