## Главная ценность (одна фраза)
Методист за минуту получает решение, которое можно защитить перед управлением образования: какой учебник реально слабее, где не хватает часов и сколько их перенести — с цифрами и доверительным интервалом, а не по среднему баллу.

## Кто платит
- Платит: управление образования области / отдел образования района (B2G-лицензия), позже — частные школьные сети.
- Пользуется: методист районного/областного методкабинета, завуч школы.
- Выгода для плательщика: решение о закупке учебников (ежегодные бюджетные деньги) опирается на измеримый результат; отчёт для акимата/министерства готов автоматически.

## Факты (проверены поиском 11.11.2026)
- Четвертная оценка = ФО 25% + СОР 25% + СОЧ 50%; СОР — по разделу программы, СОЧ — по четверти. Источник: [azattyq-ruhy.kz](https://rus.azattyq-ruhy.kz/society/97569-pravila-otsenivaniia-shkolnikov-izmenilis-v-kazakhstane-otvet-minprosveshcheniia).
- Формат СОР/СОЧ пересматривают; анонсировано (не подтверждено приказом) упразднение в 5–9 классах в 2027. Источники: [finance.kz](https://finance.kz/news/minprosveshheniya-peresmotrit-format-sor-soch), [digitalbusiness.kz](https://digitalbusiness.kz/2026-09-08/sor-i-soch-otmenyat-dlya-vseh-shkolnikov-kazahstana-poyavilsya-grafik/). Вывод: платформа принимает **любой** тест по темам, не привязана к СОР/СОЧ.
- 8 048 общеобразовательных школ: [stat.gov.kz](https://stat.gov.kz/ru/news/bolee-8-tysyach-shkol-kazakhstana-nachali-novyy-uchebnyy-god/); ~3,9 млн школьников: [inform.kz](https://www.inform.kz/ru/svishe-215-tisyach-odinnadtsatiklassnikov-okanchivayut-shkoli-kazahstana-788ab848).
- Часы алгебры 7 класса по типовому учебному плану РК поиском не подтверждены → в продукте «демо-допущение».
- Реальные названия учебников по алгебре 7 в официальном перечне поиском не подтверждены → учебники остаются «А/Б/В (демо)».

## Предпосылки (решено: согласен)
1. Ядро-отрыв — честное сравнение и «почему» у часов; новые слои не должны его заслонять.
2. Жюри оценивает глубину на живом демо: каждая новая функция работает на демо-данных, пустых кнопок нет.
3. Масштаб доказываем архитектурой и реальной БД со схемой и индексами, а не словами.
4. Нельзя тратить время на внешние аккаунты (новая БД в облаке, ключ ИИ) без Дони → решения, которые работают без них.

## Альтернативы
**A. Минимальная: всё в браузере.** Новые функции (item analysis, четверти, покрытие) в `analytics.ts`, большой JSON-набор. S, риск низкий. Минус: история масштаба — только слова.

**B. Идеальная: Neon Postgres + API + роли.** L, риск средний: нужен новый проект Neon (аккаунт Дони), миграции, авторизация.

**C. Гибрид (выбрано): Postgres-схема, исполняемая в PGlite.** Настоящий SQL Postgres (схема, индексы, агрегаты) работает в серверной функции через PGlite (WASM) на сгенерированных данных; тот же SQL без изменений переезжает в Neon. Открытый REST API `/api/v1/*` + OpenAPI, иерархия регион → район → школа → класс, роли через переключатель «Я — методист школы/района/области» (демо без входа, честно подписано). Расчётное ядро `analytics.ts` общее для браузера и сервера. M, риск низкий-средний.

Почему C: даёт настоящую БД и API для истории масштаба без внешних аккаунтов до финала; путь в прод — одна переменная `DATABASE_URL`.

## Объём к финалу (порядок слоёв, каждый — тесты → build → preview)
1. Данные v2: 3 района + область, 54 школы, 4 четверти, ~25k результатов по темам + ответы на вопросы (item-level) для одной четверти.
2. Схема БД (`db/schema.sql`) + PGlite + API `/api/v1/{regions,schools,topics,textbooks,hours}` + `public/openapi.json` + страница `/api`.
3. Иерархия и роли: фильтр уровень → район → школа; переключатель роли.
4. Item analysis: трудность p, дискриминация (point-biserial), дистракторы, флаг «плохой вопрос».
5. Динамика по четвертям + раннее предупреждение (падение ≥ 5 п.п. с ДИ).
6. Учебники: покрытие тем программы (таблица глав), карточка учебника.
7. Часы: экспорт КТП в Excel, отчёт PDF (есть).
8. Конструктор выводов без ИИ (шаблоны поверх чисел, у каждого вывода — ссылка на цифру); ИИ-аналитик — после ключа от штаба.
9. Импорт: проверка качества (пустые, вне 0–100, дубликаты, неизвестные темы) с отчётом; обезличивание (хэш ФИО).
10. EN, тёмная тема, PWA-манифест.
11. Презентация v2, видео-демо (ui-demo), питч v2.

## Что не делаем
Реальная авторизация и хранение персональных данных до пилота (закон РК о ПД); ИИ без ключа.

### CEO (стратегия и объём)
- REALITY: ширина может размыть главный вау («честное сравнение»). Решение (P1+P6): ширину делаем, но демо-путь 60 с остаётся: загрузка → трудные темы → учебники → часы → отчёт. Новые разделы — во второй строке навигации.
- REALITY: СОР/СОЧ могут отменить в 5–9 классах в 2027 → позиционирование «любой тест по темам» (импорт не завязан на СОР/СОЧ), это защищает от вопроса жюри.
- Мечта (12 мес.): область видит все предметы, отчёт к закупке учебников формируется сам, методист района получает раннее предупреждение по классам.
- NOT in scope: реальная авторизация, хранение ПД, ИИ без ключа, интеграции с Kundelik/Bilimal.
- Error & Rescue: импорт битого файла → отчёт ошибок построчно, частичная загрузка валидных строк; пустая выборка (фильтр на школу без данных) → состояние «нет данных» с подсказкой.

### Design
- Навигация: 4 → 8 разделов. Решение (P5): верхняя панель «уровень: область / район / школа» + роль; разделы в две группы («Решения»: обзор, учебники, часы; «Диагностика»: карта, задания, динамика, данные). На 375px — горизонтальный скролл вкладок (уже работает).
- Сохранить редакционный стиль (paper/ink, PT Serif); тёмная тема — те же токены, инвертированные.
- Каждая новая таблица: подпись «как читать» одной строкой, как у сравнения учебников.

### Eng
- REALITY: PGlite (WASM ~3 МБ) в serverless: холодный старт + загрузка 25k строк. Решение: синглтон на инстанс, вставка одним batch; `benchmark` после деплоя preview; если холодный старт > 3 с — агрегаты считаются из того же генератора в памяти, SQL-схема остаётся документом и миграцией для Neon.
- Ядро `analytics.ts` чистое (без IO) — переиспользуется на сервере (P4).
- Тесты (TDD) на: item analysis (p, point-biserial на известном примере), раннее предупреждение (падение с ДИ), валидацию импорта, иерархические фильтры, API-ответы (схема).
- Failure modes: деление на 0 при n<2 (sd), пустые темы, топик без часов (дефолт 6 — показать предупреждение).
